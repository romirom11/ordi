# ordi v1.0.1

Fixes the desktop app's "Connect to your ordi instance" screen failing against standard Docker deployments.

## Fixed

- **Desktop instance gate**: the connection check probed `/healthz` at the site root, but the bundled nginx forwards only `/api/*` to the API service – so the probe hit the SPA fallback and was blocked by CORS from the `tauri://` origin. The gate now probes `/api/v1/healthz` and falls back to `/api/docs/openapi.json`, so it also connects to v1.0.0 servers without any server-side update.
- **API**: `/healthz` and `/readyz` are additionally exposed under `/api/v1/` so they are reachable through web proxies that forward only `/api/*`.
- **CORS**: the Tauri desktop origins (`tauri://localhost`, `http://tauri.localhost`) are now always allowed in addition to the configured `CORS_ORIGINS`, removing a silent way to lock desktop clients out.
- **nginx**: the bundled config now proxies `/healthz` and `/readyz` to the API instead of serving the SPA fallback.
