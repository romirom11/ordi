# ordi v1.9.0

Deals learn which product they sell, lists learn multi-select, and the desktop
app gets its drag & drop back.

## Deals link to the project they sell into

A SaaS lead and a website-development lead used to be indistinguishable in the
pipeline. A deal can now point at the product or delivery project it sells
into - a real foreign key, not a label:

- the pipeline board grows **project filter chips** (All / each linked
  project / No project), which appear only once at least one deal is linked -
  zero setup, zero noise for teams that don't use it;
- kanban cards show the linked project, the deal page header gets a project
  picker with a jump-to-project link, and the new-deal dialog a project
  select;
- the MCP agent participates fully: `create_deal` accepts `projectId` (and
  its description nudges agents to set it), `list_deals` filters by project -
  including the literal `none` for unlinked deals - and returns the link.

Being a column with a constraint rather than a custom field means integrity
comes for free: you cannot link to a deleted project, and deleting a project
cleanly unlinks its deals. A generic "relation" custom-field type was
considered and deliberately postponed - jsonb values can never carry FK
guarantees, which is exactly what this link needs.

## Multi-select in lists

The CRM client table and project task lists get row checkboxes: click
toggles, shift-click extends a range, the header checkbox takes the page.
A floating bar applies bulk actions - status for clients, status and
priority for tasks, delete on both, permission-gated like their single-row
equivalents. Each row is one request, and partial failure is reported as it
is ("Updated 3, failed 1") - a stale-version conflict fails one row, not the
batch, and never masquerades as success.

## Tabs reorder by dragging

Grab a tab, drop it where it belongs; the order persists with the rest of
the tab state.

## Desktop drag & drop works again

Tauri v2 ships with `dragDropEnabled` on by default: the webview intercepts
drag events for native file drops, which silently kills HTML5 drag & drop
inside the page. In the desktop app that had broken the pipeline board, the
task board, sidebar nav reordering - everything draggable. The flag is now
off. (Verified the board logic itself in a real browser first: the deal
moved and `POST /deals/:id/move` returned 200 - the web app was never
affected.)

## Smaller things

- CRM breadcrumbs follow the app-wide pattern: parent trail only
  (CRM › Clients, CRM › Pipeline), no echo of the page title in the crumb;
  long deal titles truncate to one line with the full text on hover.
- `docs/features.md` is a living feature registry - backlog, in flight,
  shipped - so future work and past decisions live in one place.
