# ordi v1.4.0

One calendar everywhere, navigation history inside each tab, and the people you
invite finally show up before they accept.

## Dates

Every date entry used to be a native browser date input, which meant the popup
looked like whatever browser you happened to be in and the format was the
browser's rather than yours. All 21 of them now share one calendar drawn in the
app's own style: month grid, keyboard navigation (arrows, PageUp/PageDown,
Enter), a Today shortcut, and typing as well as clicking.

**Profile → Preferences** gained a date format, with a live sample beside each
option: follow the language, `dd.MM.yyyy`, `dd/MM/yyyy`, `MM/dd/yyyy`,
`yyyy-MM-dd` or `d MMM yyyy`. Whatever you pick is used everywhere a date is
written, not just in the pickers. The week starts on Monday, except in `en-US`.

Calendar days are now parsed as local dates rather than through
`new Date(iso)`, which shifted a day in negative UTC offsets.

## Pending invites

Someone you invited existed only in the invites table, so the members list
looked unchanged right after you sent one. Pending invites now sit at the top of
Settings → Users with a Pending badge and the role they were invited into, and a
menu to copy the link, send it again, or revoke it. Resending keeps the same
token and pushes the expiry out another week.

## Back and forward, per tab

Each in-app tab keeps its own navigation stack. The arrows to the left of the
tab strip and `Alt+←` / `Alt+→` walk it, so stepping into a task and back out is
one click instead of retracing the route. The browser's own back and forward
buttons stay in step with it.

## Project rail

**Members** shows three avatars and a `+N`, and clicking manages the whole
membership in place – add with search, change role, remove – without a trip
through project settings.

**Labels** gained search and inline creation: a label that does not exist yet
can be created and applied in one gesture. The menu stays open while you pick,
which multi-select always needed.

## The app and the server now know about each other

The server reports its version in `GET /healthz`, and every client compares it
with its own build:

- a browser tab that survived a server update shows a banner with a one-click
  reload;
- the desktop app warns when the instance it is connected to is *older* than
  itself, with a link to the update instructions – it can no longer drift away
  from its server silently;
- Settings shows the running version at the bottom of the navigation, and
  admins get a link there as soon as a newer release is out.

## Upgrading

Migration `0008` adds `users.date_format` and defaults it to `auto`, so existing
users see no change until they pick a format. The Docker image runs migrations
on start; there is nothing to do by hand.
