# ordi v1.22.0

A CRM usability release. Every native browser dropdown in the CRM is replaced
by an app-styled picker with search, every table gets sortable columns, and
the three record pages (lead, deal, company) trade their fixed 320px rail for
a flexible one beside full-width content – so values wrap and read fully
instead of truncating. The MCP server stops silently dropping lead research
fields, and custom fields open up to leads end-to-end.

## Searchable pickers everywhere in the CRM

- A new **SearchSelect** component replaces the native `<select>`: an
  app-styled dropdown with a search box from 8 options, keyboard navigation,
  icon and hint rows, and footer actions. It drives the lead rail's status
  and contact pickers (contact search shows positions and can create a new
  contact inline), the create dialogs' company / status / stage / currency /
  project pickers, the sales activity panel's type, template, owner, sequence
  and outcome selects, the leads table filters and bulk actions, the Work
  scope toggle, playbook selects and the company page's link-project picker.
- The lead rail's company and contact rows now carry a visible link out to
  the company record on hover.

## Sorting and filters

- **Leads** and **Clients** table headers sort on click: ascending,
  descending, back to default on the third click. Statuses sort in funnel
  order rather than alphabetically; empty values sink to the bottom in both
  directions. Selection in the clients table follows the sorted order so
  shift-range picks what the eye sees.
- Leads gain an **owner filter** beside search and status, using the API's
  existing `ownerId` parameter.
- The **invoices** and **quotes** lists – which never had a header row – get
  one that doubles as the sort controls (number, company, status in
  lifecycle order, date, amount). **Profitability by project** and the
  **time reports** table sort too.

## CRM record pages: flexible rail, full-width content

- The lead, deal and company pages share one layout: content at full width,
  a properties rail that flexes `280–400px` with the viewport instead of a
  fixed 320px, and one 1100px breakpoint.
- Rail values – company, contact, owner, project, lost reason – **wrap
  instead of truncating**; an ellipsis hid exactly the data the row exists
  to show, with no hover recovery.
- Empty Details, Qualification and custom fields render only while they can
  be filled; a read-only record no longer shows a grid of dashes.
- The lead's **next-action card became actionable**: Complete when an action
  is due, Schedule when none is planned – the empty state that the whole
  workflow exists to prevent now offers the fix, not just the warning.
- **Sales history** shows the 8 most recent rows with "Show all N"; a worked
  record used to push notes and files below several screens of history.

## MCP and custom fields for leads

- `update_lead` and `create_lead` now carry the full writable field set the
  API accepts – `suggestedChannel`, `sourceTitle`, `sourceType`,
  `signalDate`, `sourceCheckedAt` and `customFields`. Previously the SDK
  silently stripped these arguments before the PATCH, so an "update" saved
  nothing. Update fields are nullable so values can also be cleared.
- **Custom fields open up to leads**: the `leads` entity joins the shared
  enum that the API route, `create_custom_field` and the settings panel all
  validate against (the panel now imports the shared enum instead of a
  hand-copied list that had already drifted). The deal page's custom-fields
  card moved to a shared component and the lead page renders it too.
