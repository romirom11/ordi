# ordi v1.37.0

Agents can now run on Codex, including a custom OpenAI-compatible gateway or a ChatGPT subscription.

## Codex runtime

The `codex` runtime is no longer "coming soon". An agent can be created with **Claude Code** or **Codex** — `claude_code` is unchanged, both run side by side and the choice is per agent.

Codex is driven as `codex exec --json` in a per-task harness (`tasks/<taskId>/harness`), the same isolation as Claude. MCP connectors are appended as `[mcp_servers.*]` in the generated `config.toml`. The run report is parsed from `AGENT_REPORT_SCHEMA` (NDJSON + tail JSON) the same way as Claude.

## Custom OpenAI-compatible provider for Codex

A Codex credential can now carry a **Base URL**. Leave it empty for native OpenAI (`api.openai.com`); set it for any OpenAI-compatible gateway:

- LiteLLM / OpenRouter, Ollama `http://host:11434/v1`, Mistral, Azure OpenAI, corp proxy

Under the hood this writes `harness/config.toml`:

```toml
model_provider = "ordi_custom"
[model_providers.ordi_custom]
base_url = "https://proxy.example.com/v1"
env_key = "ORDI_CODEX_TOKEN"
```

Reserved provider ids `openai/ollama/lmstudio` are not overridden — the custom provider is `ordi_custom` per upstream `config-advanced`.

The credential form in **Settings → Agents** now has a **Provider** selector (`Anthropic` / `OpenAI`) and a conditional **Base URL** field (only for `OpenAI` `API key`). The credential card shows the provider and base URL. Validation: `Anthropic` cannot carry a `baseUrl`, a `subscription` credential cannot carry a `baseUrl`.

## Subscription (ChatGPT plan)

A Codex subscription credential is also supported in this release:

- run `codex login` locally, then paste the content of `~/.codex/auth.json` as the **Secret** for a `Provider: OpenAI` `Kind: Subscription` credential.

This is the upstream-documented fallback for headless/CI (`scp auth.json`). It is stored `AES-GCM` encrypted and never returned from the API, and Codex refreshes the token from the `refresh_token` inside it. A one-click Device Flow in the UI (no paste) is planned as the next step — paste remains as Advanced for Enterprise/CI.

For automated workers OpenAI recommends an API key.

## Env fallbacks

`OPENAI_API_KEY` is now also recognised as an env fallback (`env:openai`), alongside `ANTHROPIC_API_KEY` (`env:anthropic`). Either appears as a read-only card in Settings → Agents when set.

## Upgrading

`docker compose pull && up -d` (Dokploy: Redeploy). Migration `0041_codex_base_url` adds `agent_credentials.base_url` (nullable, additive). The image now installs `@openai/codex` (`npm i -g @openai/codex`); if the registry was unreachable at build time the adapter reports `codex runtime unavailable` and `Verify` explains it — rebuild once registry access returns.

## API

- `GET /agents/overview` now probes both runtimes; `installed` is per runtime key.
- `POST /agent-credentials` accepts `baseUrl` (url, nullable) with the provider/kind refine above.
- `POST /agent-credentials/:id/verify` routes by `provider` (`openai → codex`, otherwise `claude_code`).
