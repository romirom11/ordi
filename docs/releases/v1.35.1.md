# ordi v1.35.1

The bundled object storage no longer depends on MinIO's images, which are
no longer served anonymously, and the API creates its own bucket.

## Deploys with the `minio` profile failed to pull

`docker compose pull` stopped at `quay.io/minio/mc: unauthorized`. MinIO
stopped serving its images anonymously: v1.31.0 had already moved the
compose files from Docker Hub to quay.io when the Hub pulls started
answering 401, and quay.io now answers the same for `minio/mc` and
`minio/minio`, every tag included. A host without a cached image could
not pull the server either.

- **RustFS instead of MinIO.** The `minio` and `minio-init` services are
  replaced by one `s3` service running RustFS 1.0.0: Apache-2.0,
  S3-compatible, published on Docker Hub, credentials from the same
  `S3_ACCESS_KEY`/`S3_SECRET_KEY` pair. Data lives in the new `s3_data`
  volume.
- **The API creates its bucket.** On boot it checks the bucket and creates
  it when missing, retrying while the storage container is still starting,
  and never failing the boot over it. That is what the `minio/mc` init
  container used to do; now no client image is involved, and an R2/S3
  install whose key may create buckets gets the same convenience.
- **Nothing to rename in a hurry.** `COMPOSE_PROFILES=minio` still selects
  the storage service and `S3_ENDPOINT=http://ordi-minio:9000` still
  resolves to it. The recommended names are `COMPOSE_PROFILES=s3` and
  `http://ordi-s3:9000`.

## Upgrading

Server: `docker compose pull && up -d` (Dokploy: Redeploy). No migrations.

If you used the bundled MinIO, its files sit in the `minio_data` volume in
MinIO's own on-disk format, which RustFS does not read. Copy them across
while the old container still runs from its cached image: bring the new
`s3` service up next to it, run the one-off `rclone sync` from
`docs/deployment.md` §4 between `ordi-minio:9000` and `ordi-s3:9000`, then
switch `S3_ENDPOINT` to `http://ordi-s3:9000` and redeploy. The
`minio_data` volume stays until you remove it yourself. An attachment that
was not copied is reported by the API as "File is missing from storage",
never lost silently.

External S3/R2 installs are unaffected apart from the boot-time bucket
check, which only logs when the key is not allowed to create buckets.

The desktop app is unchanged apart from its version number.
