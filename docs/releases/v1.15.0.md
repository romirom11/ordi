# ordi v1.15.0

New project is a sheet.

v1.14.0 put a row of chips into the create dialog and left the rest of it
alone: a name, a key, a type and a client in four labelled boxes, then three
chips underneath, then two more date boxes. That is a form with decorations,
not the thing it creates.

It reads the way the project record does now:

- the workspace and "New project" as a trail in the header;
- the project's icon beside a borderless name that reads as a title, with a
  short summary under it;
- one chip row carrying every decision - key, type, client, visibility,
  priority, lead, members, start, target, labels - each opening its own menu,
  dates included;
- a divider, then a description that writes in the same sheet;
- a footer that keeps the visibility line in view, because that is the one
  choice with consequences for other people.

Ordi's own fields join the row rather than sitting above it. The key is a
chip that opens its input, since it is derived from the name and rarely
touched, and the client chip carries the required marker when the selected
type demands one.

Creating stays one call plus its follow-ups: `POST /projects` takes what a
project cannot exist without, one `PATCH` carries the summary, priority and
labels (project edits, not creation fields), and the members follow. A
failure in either follow-up cannot lose the project.

Each chip carries an accessible name, so the row is navigable by what a chip
is for rather than by what it happens to show.
