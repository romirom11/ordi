# ordi v1.20.0

A role holding only `kb.read` opened the knowledge base and every workspace
space was empty. Not because access control refused it – because every page
anyone had ever written was a draft. Pages were born `published: false` by a
silent schema default, the only publish control hid in the sidebar's context
menu, and the draft rule ("editors only") then did exactly what it says, to
content nobody meant to hide.

This release makes a created page a visible page, and – found while
investigating the report – makes the page-level visibility rule hold in every
place a page surfaces, not only in the page tree.

## A created page is a visible page

- New pages are born published. Draft is an explicit choice now: pass
  `published: false` on create, or unpublish later – both still work, and a
  draft still reads for the space's editors only.
- A migration marks all existing pages published. With the old silent default,
  an unpublished page recorded that nobody found the button, not an intent to
  hide – so the migration reads it that way. A page genuinely meant as a draft
  can be unpublished again.
- The UI marks the exception instead of the norm: a Draft badge with a
  one-click Publish button on the page itself, a draft icon in the tree in
  place of the green published dot that used to sit on everything.

## One rule, every surface

The page-level rule (a draft reads for editors; a `private` page for its
author and the editors) lived only in the KB list/get path. Everywhere else a
page surfaces answered on space access alone, which let each of these leak
what the tree itself refused to show:

- **Search** matched drafts and other people's private pages and returned
  their titles.
- **The home feed and per-entity activity trail** narrated their titles to
  anyone who could see the space.
- **`GET /pages/:id/versions`** returned full version bodies – the entire
  content of a page the actor could not open.
- **Duplication** copied an unreadable page into a space the actor edits,
  making the body readable in the copy.
- **Backlinks** on a public page named pages linking to it from private
  spaces.
- **The live stream (SSE)** broadcast KB page events, titles included,
  workspace-wide.

`canSeePage` is one shared function now and every one of those paths asks it.
Version history and duplication answer 404 for a page the actor cannot see,
search and the feeds filter page-level visibility on top of space access, and
KB events on the stream are scoped to the space's audience the same way
project events are scoped to the project's.

## Upgrading

The migration runs on startup as usual. If your team kept deliberate drafts,
re-unpublish them after the upgrade – everything else needs no action, and the
knowledge base a `kb.read` role sees will finally match what its editors see.
