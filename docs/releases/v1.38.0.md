# ordi v1.38.0

Agents can file subtasks and plan cycles over MCP, and a task's status can be changed straight from **My tasks**.

## MCP: subtasks and cycles

`create_task`, `update_task` and `upsert_task` take two new fields:

- `parentId` – the id of the parent task. The task becomes its subtask; `null` makes it a top-level task again.
- `cycle` – a cycle id or name (`"November"`, case-insensitive); `null` takes the task out of its cycle.

```json
{ "projectId": "CONTENT", "title": "Write the launch post", "parentId": "01J…", "cycle": "November" }
```

A parent from another project, the task itself or one of its own subtasks is refused with a message that says why, and an unknown cycle is refused with the list of the project's cycles. Nothing is written in either case.

Reading side:

- `get_project_schema` lists the project's cycles (id, name, status, dates). No MCP tool exposed them before.
- `list_tasks` filters by `parentId` (the subtasks of one task) and `cycle`.
- `get_task` and every task-writing tool answer with `parentId` and `cycleId`, so an agent can check the link it just made.

After upgrading, reconnect the MCP client so it reloads the tool list. Until then the client keeps the old schema without these fields.

## My tasks: change the status from the row

The circle next to a task name on **My tasks** now opens the same status picker as the project list, so triaging across projects no longer means opening each task. It is offered where you are an admin or member of that task's project, and the write takes part in the usual optimistic lock.

Due dates that carry a year ("17 Sep 2026"), or follow an explicit date-format preference, no longer wrap onto a second line and spill out of the row.

## API

A task's parent and cycle now have to belong to the task's own project. `POST /tasks`, `PATCH /tasks/:id` and `POST /tasks/bulk` answer `400 validation_error` for:

- a `parentId` from another project, or a deleted task;
- a `parentId` that is the task itself, or one of its own subtasks (which used to close a loop and hide the branch from tree views);
- a `cycleId` from another project. A bulk update whose selection spans projects is refused whole, before any task changes.

The subtask depth limit (5) also counts the subtasks that move with a task, so hanging a task with its own subtasks under a deep parent can no longer exceed it.

`GET /me/tasks` rows also carry the status id, the task `version` and the project's visibility.

## Upgrading

`docker compose pull && up -d` (Dokploy: Redeploy). No migrations in this release.

Tasks that already point at a parent or cycle in another project keep working; the new checks apply only when a parent or cycle is written.
