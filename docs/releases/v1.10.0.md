# ordi v1.10.0

Connecting GitHub becomes one click, and two long-standing git-integration
bugs go away.

## GitHub App: one click, no copy-paste

Connecting GitHub used to be a trail of manual steps with two dead ends: the
webhook URL lived only in the deployment docs, and the per-connection signing
secret was generated but never shown anywhere, so signature verification
could not be set up at all. The GitHub App removes the trail:

- **Create**: one click POSTs an app manifest to GitHub; GitHub creates the
  app with the webhook URL, permissions and events pre-registered and returns
  every credential through a one-time conversion code. Nothing is copied by
  hand. An org name is optional for org-owned apps.
- **Install**: GitHub's own install screen picks the repositories. The
  installation webhook creates the git connection and syncs the repo list
  automatically; `installation_repositories` keeps it in sync afterwards.
  Uninstalling flips the connection to revoked but keeps repositories,
  project bindings and task links - a reinstall revives the same connection.
- **Auth**: RS256 app JWT with cached installation tokens, plain
  `node:crypto`, no SDK dependency. Works for github.com and GitHub
  Enterprise (the API base is derived from the app's URL).

App credentials live in workspace settings with AES-GCM encrypted secrets,
manageable from Settings → Integrations; pasting an existing app's
credentials manually is also supported. The legacy per-connection webhook
path, OAuth and PAT flows keep working unchanged.

## Webhook signatures are real HMACs now

`X-Hub-Signature-256` verification used to be `sha256(secret + body)` - a
homegrown construction, not an HMAC. Real GitHub deliveries could never have
passed verification, and standard receivers could not verify ordi's outbound
webhooks either. Both directions now use a proper HMAC-SHA256. In-flight
OAuth states (10-minute TTL) were invalidated by the change.

## Branches link to tasks the way ordi names them

`parseTaskRefs()` only matched uppercase `KEY-N`, while ordi's own "Copy
branch name" button lowercases the key - so branches named exactly the way
ordi suggests never linked to their tasks. Branch names now parse
case-insensitively. Free-form text (commit messages, PR bodies) stays
uppercase-only, so "utf-8" does not become a task reference.
