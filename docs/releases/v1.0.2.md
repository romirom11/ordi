# ordi v1.0.2

Fixes a crash on the project page and a broken project key suggestion for non-Latin names.

## Fixed

- **Project page crashed with `(x.data ?? []).map is not a function`.** The properties rail and the project access panel both read the cache key `['project-members', id]` but stored different shapes – one the plain array, the other the `{ data }` envelope. Whichever request resolved last decided the shape, so opening project settings and returning to the overview crashed the page. Both now use one shared `useProjectMembers` hook with a single shape.
- **A project key is now suggested for Cyrillic names.** Key derivation stripped every non-Latin character, so a name like "Редизайн лендінгу" produced an empty key and the create form rejected it. Names are romanized first ("Редизайн лендінгу" suggests `RL`).
- **Ledger descriptions** created by the v1.0.0 backfill used an em dash; a migration rewrites them to an en dash to match the rest of the product.

## Added

- **CI guard against cache-shape collisions** (`pnpm check:query-shapes`). This class of bug caused three separate crashes, so it is now checked automatically: any query key stored in two different shapes fails the build.
