# ordi v1.43.0

**Projects can keep the credentials a client hands over**, and agents can use them without seeing them. The project overview gathers links, files, pages and secrets into one Resources block. The public intake form works again, and it can be configured and embedded on any website. The profile is split into sections.

> **Before you upgrade:** in production the server no longer starts on the all-zero encryption key, which the quick-start compose file used to default to. If your install never set `ENCRYPTION_KEY`, read [Upgrading](#upgrading) first.

## Project secrets

Logins, passwords and API keys a client sends now live with the project, as a new kind of resource.

- **Resources → Add → Secret.** Paste the client's message and it becomes fields: login, URL, password, API key. Mark the secret as test, staging, production or other.
- **Choose who can see the values:** everyone on the project, named people, or departments (sub-departments included). The dialog shows who will really be able to open it. A secret limited to people or departments is invisible to everyone else, in lists and in the project activity alike.
- **A secret opens in a side panel.** Plain fields show as they are. **Show** reveals a value for 30 seconds, and **Copy** puts it on the clipboard without showing it. The panel lists recent use, including agent runs.
- **Expiry reminders** go out two weeks before a secret stops working, and again on the day.
- **Access needs three things to agree:** the workspace role, the project role and the secret's audience. The new workspace permissions are `secrets.read`, `secrets.reveal`, `secrets.write` and `secrets.manage`. Owners get all four. Admins and Managers get read, reveal and write. Members get read and reveal. Anyone with `secrets.manage` can change a secret's audience without seeing its values, and the secret's creator is told when that happens.
- **Revealing a value is logged** as a sensitive activity entry, without the value. It is rate-limited and refused over API tokens.

### Secrets in agent runs

- A secret switched on for agents reaches an agent run on that project as an environment variable named `SECRET_<NAME>`, or `SECRET_<NAME>__<FIELD>` when the secret has several fields. The agent's instructions name the variables, never the values. Only `secrets.manage` can let agents use a production secret.
- **Values never come back as text.** They are replaced with `[redacted]` in the run log and in everything the run writes back to ordi: comments, task fields, pages and updates. If a branch's commits contain a value, the branch is not pushed, and the run says which variable it was.
- Expired secrets are left out of the run, with a note in the run log.
- MCP: `list_project_secrets` and `check_project_secret` tell an agent what exists, whether it is set and when it expires, and which variable each field becomes. No tool returns a value.

## One Resources block

The project overview has one ordered list of **links, files and knowledge-base pages** in place of the link chips and the separate Files section. Secrets appear in the same list.

- **Add** offers a link, a file upload or a page from the knowledge base (search and pin). Rows drag to reorder, and files dropped from the desktop upload straight into the list.
- Links edit in place. Files preview, download and rename. Pages open in the knowledge base. If someone cannot open a page, it is left out of their list, title included.
- Only `http(s)` links are kept. Links with `javascript:` or `file:` addresses are dropped during the upgrade and refused from now on.

## Milestones and files

- **A milestone opens in a side panel** from its name in the Plan tab. There you can rename it, set its target date, mark it done, see its progress and every task in it, and add a task straight into it.
- **Files can be renamed** with the pencil on a file row, or by double-clicking the name. Downloads use the new name, and existing links to the file keep working.
- **More disguised file names are refused** on upload, rename and mail intake: names ending in a dot (`run.exe.`), names with an invisible character inside the extension, and names with right-to-left override characters.

## Intake form

**The public intake form had stopped submitting.** Every request failed validation. It works again, and it does much more:

- **Project settings → Intake form → Customize** opens an editor with a live preview. You can set the heading, introduction, button label, thank-you message and accent colour.
- The built-in fields can be renamed, reordered, made required or hidden. The title always stays, because it becomes the task title. You can add up to 30 custom fields of nine types, from short text and email to choice and checkbox. The answers show on the triage card and go into the task description when the request is accepted.
- **Embed it on your website.** The Embed dialog gives you a script snippet (`<div data-ordi-intake="…">` plus `/api/v1/embed/intake.js`) or a plain iframe. The embedded form sizes itself to its content and follows a light, dark or automatic theme.
- The form can accept **file uploads** (when object storage is configured) and sends the requester a **receipt email**.
- **New link** replaces the form's address, so the old link and every embed of it stop working at once.
- Spam protection now survives restarts and works across instances. It also counts behind a proxy correctly: see `TRUST_PROXY_HOPS` below.

## Profile

- **The profile is split into sections:** Profile, Notifications, Security, and MCP & API. Each has its own address. On a phone the sections become a row of tabs.
- **Personal MCP connections moved here** from workspace settings. They always act as the person who created them, so they belong with that person. The old `/settings/mcp` address redirects.
- The profile's separate API token list is gone. It duplicated the one in the MCP panel, where **Create token** now sits at the top.

## Creating projects

- Lead and Members list active people only, and both are searchable. The Members menu stays open while you pick several people, and client pickers always offer search.
- A newly created private project now opens ready to edit. It used to open read-only until the page was reloaded.
- MCP: a new `create_project` tool.

## Security

- **The Codex runtime no longer inherits the worker's environment.** A worker running inside the API used to pass `DATABASE_URL`, `ENCRYPTION_KEY` and `AUTH_SECRET` to the agent.
- **The encryption key can be rotated** without reconnecting integrations. See below.

## Upgrading

**Encryption key – check this before you upgrade.** In production the api now refuses to start without `ENCRYPTION_KEY`, with a key that is not 64 hexadecimal characters, or with the all-zero development key. The quick-start compose file used to default to that zero key. The key is public, so anyone with a database dump could read the credentials stored under it.

- **If you set your own `ENCRYPTION_KEY`**, nothing changes.
- **If you use the new quick-start `docker-compose.yml`**, it generates a random key into the `ordi_keys` volume on first start and still reads data written under the zero key. Run the rotation command below once, and **back up `ordi_keys` together with the database**.
- **If you keep your old compose file**, set `ENCRYPTION_KEY=$(openssl rand -hex 32)` in `.env`, plus `ENCRYPTION_KEY_PREVIOUS=` followed by 64 zeros. Then run the rotation command.

```bash
docker compose exec api pnpm --filter @ordi/api exec tsx src/rotate-encryption-key.ts --dry-run
docker compose exec api pnpm --filter @ordi/api exec tsx src/rotate-encryption-key.ts
```

When it reports nothing left to re-encrypt, remove `ENCRYPTION_KEY_PREVIOUS`. The same steps rotate the key at any later time. See [deployment §3c](../deployment.md#3c-encryption-key).

**Behind a CDN?** The intake and careers forms read the client IP from `X-Forwarded-For`, counting `TRUST_PROXY_HOPS` entries from the right (default `1`). One TLS terminator in front needs nothing. With a CDN in front of it, set `TRUST_PROXY_HOPS=2`.

**API changes:** `PATCH /projects/:id` no longer takes `links`. Project links are now resources (`GET/POST /projects/:id/resources`, `PUT /projects/:id/resources/order`, `PATCH/DELETE /project-resources/:id`).

**Three migrations, applied on start:**

- `0044` moves each project's links and files into the new `project_resources` table and drops `projects.links`.
- `0045` adds project secrets and grants the new `secrets.*` permissions to existing roles.
- `0046` adds the intake form configuration and the custom answers.
