# ordi v1.26.0

The requests-and-people release: intake grows a mailbox UI, attachments and a
Slack slash command; the People module opens up (anyone can read the
directory and the public slice of a card, leave is self-service on the
profile) and gets a deep hardening pass; custom fields learn project scope;
and the detail-card rails become resizable.

## Requests (intake)

- **Mailbox settings UI**: the IMAP mailbox the backend always supported is
  now configured in the project's intake settings (host, port, TLS, user,
  write-only password, folder), with a disconnect action and an explanation
  of the unseen-mail contract.
- **Email attachments survive**: files on inbound mail are stored (size cap,
  blocked extensions, max 10 per mail), shown as chips on the triage card
  (project-member gated), and re-bound to the created task on accept – the
  client's brief lands in the task's Files section.
- **`/ordi` in Slack files a request**: a signed slash command creates an
  intake item on the channel-bound project; the Events API endpoint answers
  the url_verification handshake. The Slack signing secret is configured in
  Settings → Integrations (or `SLACK_SIGNING_SECRET`).

## People opens up

- **Anyone signed in reads the directory and opens an employee card** – the
  API serves a public slice (name, position, department, manager, status,
  location, birthday) plus the custom-field groups the viewer holds a grant
  on; contacts, employment dates and the rest still need `people.read`.
- **Leave is self-service**: a "My leave" card on the profile (balances, own
  requests, file/cancel) and an approvals block for the manager – neither
  needs any `people.*` permission. `GET /leave-requests?scope=approvals`
  returns the requests waiting on the current user.
- **Holidays get a settings panel** (calendars + days) and finally count:
  leave-day math skips public holidays instead of charging them.
- **Employee documents carry their own permission** (`people.read_documents`,
  granted by migration to roles holding `people.read`), document files are
  bound to the employee so their signed URLs answer to that permission, and
  existing files are claimed by migration.
- **Field-group WRITE grants do real work**: a role granted write on a group
  edits exactly those fields via the card, without `people.write`.
- **Employee card**: a location field (country/city), a slimmer hero (identity
  only; email and the account marker move to Basic info), custom-field labels
  keep their typed case.

## People hardening

- PATCH `/employees/:id` merges custom fields instead of replacing the blob
  (an MCP client sending one field no longer erases the questionnaire) and
  confirms the optimistic-locked update; audit records log only touched keys
  and never custom-field values.
- Leave decisions run in one transaction with the request row locked – two
  concurrent approvals no longer deduct the balance twice; the fallback
  approver is deterministic.
- Lifecycle validates transitions (double exit refused, reactivate clears the
  exit date, onboarding runs its checklist once); hiring an applicant is
  idempotent; soft-deleted employees drop out of leave lists, balances and
  blocking counts.
- Read-only API tokens can no longer write compensation, overhead settings or
  questionnaire answers; creating compensation requires `people.write`; the
  People module toggle now covers the real HR route segments.

## Custom fields

- **Project-scoped custom fields**: task fields defined in the project's
  settings exist only in that project, on top of the workspace-wide ones; the
  project admin manages them without `settings.manage`. Keys cannot shadow a
  global field; different projects may reuse a key.
- The task card's custom-fields block is **collapsible** (persisted; starts
  collapsed while every field is empty).

## UI

- **Resizable rails**: the right-hand properties sidebar on task, project,
  lead, deal and company cards is drag-resizable (default width is the
  minimum, up to +50%), persisted per rail kind; double-click resets.
- **Avatars fixed**: profile photos render in the desktop shell (stored paths
  are resolved before hitting the webview) and record history shows the
  actor's avatar instead of a generic icon.

## Release pipeline

- The GitHub release is created as a **draft** and published only after every
  desktop platform uploaded its bundle – the updater and download page never
  see a version whose binaries do not exist yet; `/desktop/latest` retries
  after a minute while the downloads list is empty.
