# ordi v1.8.0

Deals become first-class, and the MCP agent stops being read-mostly in CRM.

## Deals get a card of their own

A deal used to exist only as a kanban tile: clicking it jumped to the company
page, and there was nowhere to see a deal's own history or notes. New
`/deals/:id` page:

- editable title, stage dropdown right in the header (moving to a lost stage
  prompts for a reason, same as the board), a link back to the client, owner
  picker;
- editable amount, currency and expected close date, the lost reason for
  lost deals, and the deal's custom field values;
- deal-scoped notes with the same rich-text editor companies have;
- an activity trail from the audit log: who created, moved and edited what,
  and when.

Kanban cards and the deal list on the company page now open the deal; the
company stays one click away via the header chip and the card's context
menu. CRM breadcrumbs grew up along the way: instead of a lone "CRM" link
you get full trails - CRM › Clients › Acme, CRM › Pipeline › Website
redesign - with every level clickable.

## The agent can create CRM records

The MCP catalog could read companies and append notes, but not create
anything in CRM - and `move_deal` demanded a `stageId` that no tool could
produce. Six new tools close the surface:

- **`create_company`**, **`create_contact`**, **`create_deal`** - guarded by
  the same `crm.write` / `deals.write` permissions as the web app, logged to
  the activity feed with `actor_type=agent` like every other mutation.
- **`list_contacts`**, **`list_deals`**, **`list_deal_stages`** - compact
  rows through the same scrub pipeline as the other list tools, so ids
  (including stage ids) are discoverable instead of guessable.

## Agents can define custom fields

`create_custom_field` defines a field on any supported entity (companies,
contacts, deals, projects, tasks, invoices, quotes, employees, applicants)
with the full type set - text, number, date, select, multiselect, checkbox,
url, user. It requires `settings.manage` in the token scope, enforced
server-side. `list_custom_fields` enumerates definitions, and the create
tools accept a `customFields` argument so an agent can fill the fields it
just defined. Custom-field definition changes now write audit records - they
were silent before, from any client.

## Multi-line agent text stays multi-line

Notes, task comments and KB pages written through MCP used to collapse into
a single paragraph - every line break lost, one wall of text. Agent text is
now converted properly: blank lines separate paragraphs, single newlines
become hard breaks. `create_note` can also attach to a contact or a deal,
not just a company.

## The dashboard respects who's asking

The home dashboard's recent-activity feed filtered only by sensitivity, so a
Member without `finance.read` still saw that payments were recorded on
invoices. The feed now also filters by entity domain: each entity type maps
to the permission required to see it, unknown types are admin-only, and your
own actions are always visible to you. CRM notes joined the audit trail at
the same time - creating, editing or deleting a note leaves a fact-only
record (the note body itself stays out of the diff).
