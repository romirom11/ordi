# ordi v1.5.1

Fixes "Sign in with browser" in the desktop app, which could fail without ever
opening a browser.

## What was wrong

Four separate faults, each enough to break the flow on its own:

- **PKCE hashing needed `crypto.subtle`**, which only exists in a secure
  context – and the desktop app runs on the `tauri://localhost` origin, which
  several platforms do not treat as one. The very first step threw, so no
  browser ever opened. Hashing no longer depends on it.
- **`ordi://` deep links started a second process** on Windows and Linux, so
  the window waiting for the code never heard about it. The single-instance
  plugin now forwards the URL to the running app.
- **The PKCE verifier lived in `sessionStorage`**, which a relaunched app
  cannot read. It moved to `localStorage` with a ten-minute expiry.
- **A cold start delivers the link as a launch argument**, not an event; the
  login screen now reads that too. Windows and Linux also register the
  `ordi://` scheme at runtime, which dev and portable builds never got.

## What you see now

Failures say which step failed instead of one catch-all message: the server
could not be reached, or the browser could not be opened. When only the
browser fails to launch, the sign-in stays live and the link is shown so you
can open it yourself.

And the login screen has a box for the code the browser displays – the way in
that works even when deep links do not, which is routine on Linux.

## Upgrading

No schema changes. The fixes live inside the desktop build, so the app has to
update itself to v1.5.1 before browser sign-in works; email and password are
unaffected.
