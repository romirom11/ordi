# ordi v1.5.5

The top of the sidebar stops competing with the macOS window buttons, and the
workspace dropdown is gone: everything it hid now has a visible home.

## The workspace name moved below the window buttons

v1.5.4 put the workspace name *beside* the traffic lights by indenting it
84px. That kept one tidy row, but it also meant the name started a third of
the way into a 224px sidebar, and the indent only made sense on macOS.

The sidebar now opens with a short empty strip that belongs to the window
buttons – `trafficLightPosition` centres them inside it – and the workspace
name starts below, flush with the sidebar's left edge on every platform. The
strip is a drag region, so the corner still moves the window. Tabs are
unaffected: they live in the right-hand column and still share the row with
the window buttons.

On Windows, Linux and in the browser there is no strip at all; the name sits
at the very top as before.

## The workspace dropdown is gone

A dropdown that hides two links is worse than two visible links. The
workspace name is now a label, and what its menu used to hold has moved to
where each item belongs:

- **Settings** is a navigation row at the foot of the nav, with a gear icon
  and an active state, because it is a destination and now reads like one.
  It appears only for users who can manage settings, users or roles.
- **Invite user** is gone from the sidebar. It lives in Settings → Users,
  which is where inviting actually happens.
- **Download the desktop app** moved into the account menu at the bottom
  (browser only – inside the app it was always pointless).

## Smaller fixes

The unread badge on the notification bell used to sit on the button's corner
and, at two digits, covered most of the bell glyph. It is pulled clear of the
icon and still stays inside the sidebar.

## Upgrading

No schema changes, nothing server-side. The macOS window-button placement
changes with the app build; the sidebar changes apply everywhere, including
self-hosted web.
