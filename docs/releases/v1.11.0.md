# ordi v1.11.0

The CRM module grew up: record pages you can actually work in, modelled on
how Attio and Pipedrive structure theirs.

## Everything on a record edits now

The company page used to allow editing only the name, status and owner -
everything else was read-only even though the API supported more. Now:

- company properties (domain, billing email, currency, payment terms) edit
  inline - click the value, type, Enter; the input selects its content on
  focus so typing replaces instead of appending;
- contacts have edit and delete actions, and the primary star toggles with
  a click;
- notes are Notion-style: click the text and you are editing in place, the
  caret lands at the end, clicking away saves, Esc discards. No separate
  edit button, no separate form.

## Files on companies and deals

Both record pages get a Files section - proposals, briefs and PDFs attach
right to the record. Uploads go through the app's standard presigned-S3
path (MinIO in the dev compose, any S3-compatible store in production),
downloads are presigned links, deletes confirm first. Listing requires the
entity's read permission, uploading and deleting its write permission, and
both leave activity records.

## Custom fields edit on the deal page

Every field type gets its own control: select and multiselect as menus,
checkbox as a toggle, dates through the app's DateField, user fields as an
avatar picker, text/number/url as click-to-edit values. An agent can define
a field and fill it via MCP; a human can now correct it from the page.

## Projects from the client's card

The + on a company's Projects card opens a menu: create a new project in a
modal right on the page with the client preselected, or link an existing
project that has no client yet. The old flow navigated away to the projects
page with dialog state encoded in the URL - which meant the browser's Back
button could resurrect a closed dialog. Modal state now lives only in
component state; Back navigates, nothing else.

## Smaller things

- Detail tabs are named after what they hold: the client's name, the deal
  title, the invoice number - not "CRM" or "Finance".
- Tooltips render through a portal and clamp to the viewport, so a phone
  number on the rightmost column is no longer cut off.
- Property values wrap instead of hiding behind an ellipsis; payment terms
  read "14 days" again while staying editable; side rails widen to 320px.
- The deal page's expected-close date uses the app's DateField and follows
  your date-format preference - the last raw native date input is gone.
- MCP write tools decode HTML entities at the boundary: agent-scraped text
  like "Co-founder &amp;amp; CEO" stores as plain "Co-founder &amp; CEO".
