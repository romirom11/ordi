# ordi v1.2.0

Two things that were more friction than they needed to be: signing in to the
desktop app, and finding the desktop app in the first place.

## Sign in to the desktop app through your browser

The desktop app no longer asks for your email and password. It opens your
browser, where you are already signed in, you approve the device, and the app is
authorized – the same flow as Linear, Slack and Figma.

It uses PKCE: the app keeps a secret it never sends, and hands the browser only
its hash. A different local application that registers the `ordi://` scheme and
intercepts the callback still cannot exchange the code for a session. Codes are
single use and expire after ten minutes. Password sign-in still works.

Approving a device is written to the audit log, so you can see which machines
were authorized and when.

## Download the desktop app from inside ordi

**Workspace menu → Download desktop app** shows the current version with the
right installer for your platform first, and the others below it. No trip to
GitHub.

The release metadata comes from the public releases API and is cached for an
hour. Instances without outbound network access simply link to the releases
page instead. Forks can point this at their own repository with
`DESKTOP_RELEASES_REPO`.

## Fixed

- **Inviting someone failed with a 500 when SMTP was unreachable.** The invite
  was created and then the whole request failed on the mail send, so the screen
  showed an error for an invite that actually existed. The invite now comes back
  with its link and a clear "email not sent" warning, and only the delivery is
  reported as failed.
- **A blocked SMTP port hung the request for two minutes.** The connection
  timeouts were being passed as message defaults rather than transport options,
  so nodemailer's two-minute default applied. SMTP_URL is now parsed into
  explicit options with a 10-second connect timeout.
- **New: Settings → Integrations → Email** has a "Test connection" button that
  says whether outgoing mail actually works and why not. Hosting providers block
  outbound SMTP often enough that the failure deserves a real diagnosis instead
  of mail silently never arriving.
