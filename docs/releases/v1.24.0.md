# ordi v1.24.0

The HR release: People grows into a full HR module with a team calendar and a
configurable, access-controlled questionnaire; the knowledge base learns to
host PDF documents; list views stop forgetting their filters; and the first
end-to-end suite guards it all in CI.

## Knowledge base: PDF pages

- A page now has a type – **article or PDF**. The create dialog offers the
  choice; a PDF page takes an uploaded file (the existing attachments
  pipeline) and renders it inline through the browser's native viewer, with
  open-in-new-tab and file replacement for editors.
- Markdown export of a PDF page emits a signed link to the document instead
  of an empty body. PDF pages carry their own icon in the tree.

## HR module

- **People is now HR**, and everything people-related stays inside it:
  Employees, Leave, **Calendar** (new), Recruiting, Org, Dashboard.
- The **team calendar** is a month grid of approved and pending absences
  (name + leave type, pending faded), public holidays from the holiday
  calendars, and birthdays – a new employee field that recurs yearly straight
  off the card, so an updated date moves the event by itself.
- The **employee card** shows the work email (the login account), join date
  and birthday, plus a **Documents** section with upload, inline PDF preview
  and removal. Personal contacts (personal email, phone, telegram, …) are
  deliberately NOT hardcoded – they live in custom fields, grouped and
  access-controlled like everything else.

## Field groups: access-controlled custom fields

- A custom employee field can join a named **field group**, and a group is an
  access boundary. Who sees which group is a matrix in Settings → Roles:
  rows are groups, columns are roles plus the dynamic **Self** principal –
  the person the record is about. Roles holding `people.write` (HR) always
  keep full access.
- Enforcement is server-side: reads strip the values of groups the viewer
  holds no grant on, and the self-service endpoints accept only self-writable
  keys.
- Groups the Self principal can write become the **HR questionnaire** – a
  card on the profile page where a person fills in their own record, with a
  fill-status badge (empty / partial / complete) and a last-updated stamp HR
  sees on the employee card. Nothing is hardcoded: the questionnaire is
  whatever groups and fields the workspace defines.

## Icons on fields and groups

- Both custom fields and field groups can carry an **icon** from a curated
  set, picked in their edit dialogs. Icons render wherever the field or
  group shows: record cards, the questionnaire, the settings lists and the
  access matrix.

## Custom fields visible everywhere

- The custom-fields card now renders on the employee card, companies,
  projects, tasks and invoices; contacts edit theirs inside the contact
  dialog. (It used to exist only on leads and deals – a field defined in
  settings for any other entity was invisible.)

## Lists remember their state

- Sorting, filters, search text and chosen tabs across CRM, projects,
  my-tasks, finance, time, people and per-project task filters survive
  navigation (localStorage-backed, validated on load). A remembered tab
  behind a lost permission falls back to a visible one.

## Fixes

- Notification emails no longer arrive half-empty: task title, status name,
  actor and KB page titles are filled from current state, page mentions
  deep-link to the page, and the workspace logo (a data: URI mail clients
  refuse) is served from a new public route.
- The date picker grew **year and month grids** behind its title – picking a
  birthday no longer means paging month by month through two decades.
- Comment avatars show the author's profile photo instead of initials.

## Testing

- New **Playwright e2e suite** (`pnpm --filter @ordi/web e2e`): a real
  Chromium drives the real API + web + a throwaway S3 mock through four
  scenarios – KB PDF creation via the dialog, the article editor path, the
  HR calendar on real data with view-state persistence, and the
  questionnaire round-trip from profile to card. CI runs it in its own job.
- 9 new API tests pin the field-group access rules.
