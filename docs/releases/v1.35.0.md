# ordi v1.35.0

Invoices that look like invoices, a public invoice page that opens, and
requisites entered once instead of per document.

## The PDF is a branded document again

Every invoice and quote PDF a real deployment produced was the monospace
fallback: the branded template rendered only through the Typst CLI, and no
image ever shipped it. The fallback used a built-in PDF font that covers
WinAnsi only, so a Ukrainian invoice printed boxes where the Cyrillic was,
and it knew nothing about the logo, the accent colour or the payment
details set in Settings → Invoices.

One pdfkit renderer replaces the Typst-or-fallback pair, in process, with
no optional binary:

- **Accent bar and colour, workspace logo** (PNG or JPEG), the document
  number in the accent colour.
- **Both parties' requisites**: the issuer's legal name, tax id, address,
  email and phone on the left, the client's legal name, tax id, address and
  billing email as "Bill to".
- **Line items that wrap and paginate**: long descriptions break onto
  further lines, a long invoice runs onto further pages with the table head
  repeated, and every page carries its number and the public link.
- **Totals** with discount and tax rows, an accent "Balance due" band on
  invoices, **the workspace's payment details**, notes, terms and the
  footer note.
- **Liberation Sans** (SIL OFL, bundled under `apps/api/assets/fonts`), so
  Cyrillic and the rest of Latin render; labels follow the document's
  language (uk/en) as before.

A truncated PNG logo is skipped rather than handed to pdfkit, whose chunk
walk never returns on one and would have hung the whole API on a single bad
upload.

## The public invoice page opens

The link in every invoice email and PDF (`/i/<token>`) answered with the
raw JSON the page fetches. The API serves the SPA itself in production, and
the public API mounted at the root won over the SPA for the same path. A
browser navigation (a GET whose `Accept` prefers `text/html`) on `/i/`,
`/q/`, `/portal/`, `/intake/` and `/careers/` is now answered with the page
before the public router sees it; fetches still get the JSON, and so do
non-browser clients. Public `/i/:token/pdf` returns the PDF above instead of
a 501, and `/q/:token/pdf` is new.

The public quote page read a flat payload the API never sent and rendered
empty. It consumes the nested one, shows the branding, both parties and a
PDF link. Public documents are labelled in the language they were issued
in rather than the browser's guess.

## Requisites live in one place

- **Yours**: Settings → Invoices → "Your details" (legal name, tax id,
  address, email, phone). Stored as the workspace's `legal_details`, which
  the schema had all along without a way to edit it.
- **The client's**: the company page → "Billing details" (legal name, tax
  id, address). Stored in `companies.address`, which now has a fixed shape
  (`legalName`, `taxId`, `address`) instead of an arbitrary object.
- **Default notes and terms**: Settings → Invoices. Every new invoice and
  quote starts with this text when the caller sends none – the web form,
  invoices generated from time entries and the MCP tools alike. An explicit
  empty string still opts out.

All three print on the PDF, the public page and the invoice page in the
app, which gained "From" and "Bill to" blocks, inline editing of notes and
terms, and an absolute public link (a relative one pointed into the desktop
shell's own origin).

## Sending an invoice sends it, or says why not

"Send" flipped the invoice to sent and toasted success even when nothing
went out: with no SMTP configured the API only logged a line, and with no
billing email on the company it skipped the email entirely.

- **The button knows whether mail can go out.** Without SMTP it is disabled
  with the reason, and the page says where to configure it (Settings →
  Integrations).
- **A confirmation before anything is sent**: from whom, to whom (editable,
  prefilled with the company's billing email), the subject, the message and
  the attachment. The API refuses a send without a recipient or a mail
  server before anything changes.
- **The real outcome.** A transport failure (a refused connection, an
  unknown host, a rejected address) comes back as that error, stays visible
  in the dialog, and the invoice stays a draft. A success toasts
  "Sent to <address>", and the timeline lists every send with its address.
- `GET /invoices/:id/send-preview` backs the dialog; the send response
  carries the delivery; quotes get the same refusals. Ukrainian invoice and
  reminder emails no longer end the due-date sentence with "р..".

## Also

- Logos now upload as PNG: pdfkit cannot embed WebP. An existing WebP logo
  is still shown on web pages but skipped on the PDF; Settings → Invoices
  says so when that applies, and a re-upload fixes it.
- `docs/deployment.md` no longer suggests installing Typst;
  `docs/architecture-decisions.md` describes the renderer.

## Upgrading

`docker compose pull && up -d` (Dokploy: Redeploy). No migrations: the new
fields use the existing `workspace_settings.legal_details`,
`workspace_settings.invoice_settings` and `companies.address` columns. A
company whose `address` held keys other than `legalName`, `taxId` and
`address` keeps them in the database but the UI edits only those three.
After the upgrade: re-upload the logo in Settings → Workspace if it was
stored as WebP, fill in your requisites and default terms in Settings →
Invoices, and each client's requisites on its company page.

The desktop app is unchanged apart from its version number.
