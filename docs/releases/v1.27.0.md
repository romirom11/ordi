# ordi v1.27.0

The faces-and-friction release: profile photos show up everywhere a person is
named, the Slack integration sets itself up from one pasted token, the
recruiting tab can finally hire without the API, and every company picker is
sorted and searchable.

## Profile photos everywhere

- **Historical records keep their people**: `/users/lookup` now includes
  deactivated users (with an `isActive` flag), so comments, audit rows,
  project members and activity feeds keep the person's name and photo instead
  of degrading to "Someone" or ULID initials. Assignment pickers still offer
  only active users; renderers never filter.
- **APIs that name people now carry their photo**: leave requests join the
  employee's user, the dashboard's team events project the avatar for
  absences and birthdays, the people directory stops hardcoding
  `avatar: null` for standalone employees, and task assignees include the
  avatar column.
- **Initials give way to photos** across the task rail's assignee chips, task
  activity audit rows, the team calendar's absence and birthday chips, the
  dashboard team card, leave rows in HR and the profile approvals block, the
  employee card's manager row, the @mention dropdown and the sidebar account
  menu. Resourcing switches from the admin-only `GET /users` to the open
  lookup, so non-admins see names and photos instead of raw ids.

## Recruiting

- The recruiting tab's empty state said "create an opening" and offered no
  way to do it – creation lived in the API/MCP only. It gains a **"New
  opening" dialog** (title, department, employment type, status, positions
  count) in the toolbar and the empty state, and an **"Add applicant"
  dialog** (name, email, phone) for candidates arriving outside the public
  careers form. Creating an opening selects it.

## Slack setup, three ways easier

- **One-click app creation**: paste a Slack app configuration token on the
  settings card and press one button – the server creates the app via
  Slack's Manifest API with this instance's slash-command and OAuth URLs
  baked in, then stores the returned client id, client secret and signing
  secret encrypted. New `POST /settings/integrations-config/slack-app`
  (`settings.manage`); Slack errors surface as validation messages.
- **A setup guide with a ready manifest**: for the manual path, a collapsible
  guide walks through creating the app "From a manifest", with a copyable
  JSON manifest that already carries this instance's URLs and bot scopes.
  Event subscriptions are deliberately absent: Slack verifies that URL at
  creation time, before the signing secret can possibly be stored here.
- **A channel picker that explains itself**: channels come back sorted
  alphabetically, private ones carry a lock icon instead of `#`, the
  dropdown footer explains that `/invite @ordi` in a private channel makes
  it appear (Slack only reveals a private channel to a bot that is already a
  member), and an empty search shows a "no matches" note instead of a blank
  void.

## Company pickers

- Company dropdowns showed the 50 newest companies in ULID order – which
  reads as random – with no search and older companies missing entirely.
  Now: a locale-aware, case-insensitive **alphabetical sort** everywhere a
  company is picked (new-project modal, project properties rail, new
  lead/deal dialogs, the leads company filter, finance invoice/quote and
  subscription forms), **type-to-filter search** on the project pickers via
  the existing SearchSelect, and lookups fetch **up to 200 companies** (the
  API maximum) instead of the newest 50.

## Migrations

None.
