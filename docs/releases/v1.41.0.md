# ordi v1.41.0

**Bitbucket** joins GitHub: connect a workspace, bind its repositories to projects, and branches, commits and pull requests land on their tasks. The desktop app now hands sign-ins to your browser, new installations open on Glass Dark, and a knowledge page no longer gets stuck on "Saving…".

## Bitbucket Cloud

**Settings → Integrations → Bitbucket** connects a Bitbucket Cloud workspace with a token:

- an **Atlassian API token** together with your Atlassian email (works on every plan), or
- a **workspace, project or repository access token** (leave the email empty).

ordi checks the token by listing the workspace's repositories before it stores anything. To rotate the token, connect the same workspace again; repositories, project bindings and task links stay.

There is no webhook to copy by hand. When you **bind a Bitbucket repository to a project**, ordi registers a signed webhook on it. If the token is missing the webhook permission, the repository is still bound and ordi tells you why the webhook failed. The **Sync** button on a connection refreshes the repository list and the webhooks of bound repositories.

After that it works like GitHub:

- branches, commits and pull requests that mention a task key link to the task;
- a pull request's state follows it (open, merged, declined), and the automation rules move the task with it;
- the key is also looked for in the pull request's source branch, since Bitbucket titles a pull request after its last commit.

**AI agents** clone, push and open the pull request on Bitbucket too.

The token needs to read repositories and pull requests, and to read and write webhooks. Agents also need write access to repositories and pull requests. The card lists the exact API token scopes.

Not covered: Bitbucket Server / Data Center. Removing a connection in ordi does not delete its webhooks on Bitbucket.

## Desktop app

- **Sign-ins open in your browser.** Installing the GitHub App, GitHub OAuth, Slack and MCP connector authorization used to take over the app window and strand you on the web build of ordi. They now open in the system browser, the app shows "Continue in your browser", and it picks up the result when you switch back.
- **MCP connector sign-in completes** in the desktop app. Before, its callback needed a session the desktop app could not have. A connector authorization started before upgrading has to be started again.
- **Swipe with two fingers on the trackpad** to go back and forward, on macOS (with the native slide) and Linux.

## Look and feel

- **New installations start on Glass Dark.** Anyone who already picked a theme or style keeps it.
- **The sidebar and side panels slide** instead of popping in, and the slide no longer stutters on Glass.
- **The GitHub button** reads **Choose repositories** once the app is installed.
- **Intake settings** show only what applies: the form link only while the public form is on, and the mailbox section folded to **Connect mailbox** until a mailbox is set up.

## Fixes

- **A knowledge page (or task description) stuck on "Saving…" for good.** If you pressed Save while someone else's edit was reaching the page, and your save was refused after their version had already arrived, the page waited for a newer version that never came. **Keep my version** then did nothing, and your text was never saved. Now the conflict shows at once and Keep my version saves.

## Upgrading

No migrations.
