# ordi v1.42.0

**A deleted project can be restored**, and deleting one stops everything it was still doing on its own. Project settings open right from the project list. CSV import and export round-trip: edit an export, import it back, and records update instead of doubling. The desktop app updates quietly, and swiping back no longer slides the whole window.

## Deleting and restoring projects

Deleting a project used to hide it and little else. Its key stayed taken for good, nothing could bring it back, and parts of it kept running or showing up.

- **Deleted projects** on the Projects page (the bin icon, for anyone who may delete projects) lists them with a **Restore** button. A restored project comes back with its tasks, time, files, recurring tasks and intake.
- **The key is free again.** A new project can use the key of a deleted one. If that happens, restoring the old project is refused and names the project that now holds the key.
- **On delete, a running timer is saved** as a time entry instead of being lost, and the project's **agent runs stop**: queued ones are cancelled, a running one is asked to stop.
- **Nothing runs for a deleted project:** recurring tasks and invoices, cycles and intake mailboxes wait until it is restored, and the public intake form answers "not found".
- **A deleted project no longer shows up** in time entries, time reports, unbilled hours, the time export, the finance dashboard, a client's overview in the CRM, or the knowledge base (its project space is hidden too, even when workspace-visible).
- **Former members** can no longer change its tasks through bulk edits, and deactivating someone no longer hands its tasks to their successor.
- **A project type used only by deleted projects** can now be deleted. Those projects move to another type.

The delete confirmations now say what happens and point to the trash. To only put a project out of the way, set its status to **Archived** instead.

## Project settings

- **Open settings** in a project's right-click menu on the project list opens the settings panel over the list. It used to take you into the project first.
- The settings panel ends with a **Danger zone** with **Delete project**, for project admins who may delete projects. Before, deleting was only possible from the right-click menu.

## CSV import and export

**Settings → Import & export** caught up with the records it covers.

- **Import updates instead of duplicating.** A row with the `id` of an existing company, contact or lead updates it; for tasks the reference does it (`WEB-12`). Only the columns in the file change. The dry run and the result say how many rows are new and how many update.
- **Leads** round-trip every field the importer can take (pain signal, evidence, why fit, why now, source, signal date, caution and more). A lead that has ended or waits in nurture keeps its status: a file cannot reopen it.
- **Tasks** export and import with the same columns: ref, project key, title, status (by name), priority, start and due date, estimate. Importing needs member rights on the project; someone who could only view a project could add tasks before. Imported tasks keep the order of the file, appear in each task's history, and reach webhooks; Slack is not sent one message per row.
- **Imported companies** get an owner and a client portal link, like companies added by hand.
- **Files saved by Excel with semicolons** (as it does in Ukrainian and other decimal-comma locales) import.
- **Choose file** loads a CSV instead of pasting it, and the page is translated.
- **The time export** can be limited to a period, and an entry without a rate shows an empty cell instead of 0.
- **Exported text that a spreadsheet would run as a formula** (starting with `=`, `+`, `-` or `@`) is saved so it opens as text. Importing the file back restores the original text.
- The "Imported" notice no longer appears after a dry run.

## Desktop app

- **Updates download quietly.** The app looks for a new build at launch, every 30 minutes and whenever the server moves ahead. Nothing interrupts you: once a build is ready, an **Update to vX** row appears in the sidebar above Settings, and a click installs it and relaunches. The banner over the content and the restart toast are gone. On macOS a downloaded build is also applied when you quit the app.
- **Swiping back and forward no longer slides the whole window.** The page stays put, an arrow slides in from the edge of the window, and the swipe steps through the active tab's own history instead of landing on another tab's page. Content that scrolls sideways, such as the pipeline board, keeps the swipe until it reaches its edge.
- In the web app, the first page change after a server update loads the new version (once per version), with the same sidebar row offering a reload in the meantime.

## Upgrading

One migration, applied on start: `0043` makes a project key unique among projects that are not deleted.
