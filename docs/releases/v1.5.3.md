# ordi v1.5.3

Fixes the desktop version banner promising an update it could not deliver.

When the server is newer than the app, the banner said "Restart the app to
update" – but restarting applies nothing unless a matching desktop build is
already published and staged, and the restart call itself could fail without
a trace. Right after a server deploy the desktop build is usually still being
built on CI, so the button did nothing, silently.

The button is now **Update now** and tells the truth at every step:

- it runs the updater on demand; if a build is out, it downloads it and the
  button becomes **Restart now**, which really applies it;
- if the build is not published yet, it says so - and the app will pick it up
  by itself once it is;
- if the check or the restart fails, it says that too, instead of doing
  nothing.

Restart also no longer depends on the process plugin's injected global: it
falls back to a raw invoke, so the click always does something observable.

## Desktop links no longer say tauri://localhost

Everything that shows or copies a link – the MCP connect URL, copy-link on
tasks, projects, invoices, KB pages and tabs, the OAuth redirect URL shown in
integration settings – built it from the window origin, which inside the
desktop app is `tauri://localhost` and opens nowhere. All of them now use the
configured instance URL on desktop; the web app is unchanged.

## Realtime finally works on the desktop

The live-update stream used the browser's EventSource, which cannot send an
Authorization header and only accepts a URL on the window's own origin – on
the desktop that meant `tauri://localhost` and no credential, so realtime
never connected there at all. The stream is now read over plain fetch with
the same credentials the rest of the app uses (cookie on the web, bearer on
desktop), against the configured instance URL.

While testing it: live events for created or completed *projects* never
refreshed the projects list on any platform – the event-to-cache map simply
had no entry for them. Added.

The invoice PDF button also opened a relative URL, which inside the desktop
shell points nowhere; it now opens the instance URL in your real browser.

## Keeping this class of bug out

CI gained a check (`pnpm check:desktop-safe`) that fails when code uses
browser idioms known to break inside the desktop shell – `window.location.origin`
in links, `crypto.subtle`, `EventSource`, `sessionStorage` – outside the one
file where each is handled properly. It runs in milliseconds, so mistakes
cost a red check instead of a broken desktop release.

## Upgrading

No schema changes, no server changes of substance. The fix lives inside the
desktop build: apps update to v1.5.3 through the normal auto-update.
