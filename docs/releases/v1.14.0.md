# ordi v1.14.0

A day of using v1.13.0 produced six reports. One of them crashed the page,
one made a project visible to people who were never added to it, and four
were the same shape as the MCP work in the last release: something the app
could write and then never read back or correct.

## Changing a project's visibility crashed the page

A `<Spinner>` renders a `<div>`, and it sat inside a `<p>`. The HTML parser
closes a paragraph when a block element opens inside it, so React's tree and
the real DOM disagreed about where that spinner lived - and removing it when
the save landed threw `NotFoundError: The object can not be found here`.
WebKit, which is what the desktop app runs on, turns that into a crashed
page; Chromium only logs a warning, which is how this reached a user before
it reached a test.

The spinner is a `<span>` now, so no caller can reopen the hole: a spinner
belongs next to text, in a paragraph, a button, a label.

## A project's access is decided when it is created

Visibility, lead, members, start and target dates are chosen in the create
dialog, on one chip row. Visibility used to be assumed workspace-wide with
nothing on screen saying so, which is how a project "nobody was added to"
was visible to everybody, and it now defaults to private. The creator is
never re-added as a member on the way out - project creation already makes
them an admin, and upserting them as a plain member would take that away.

## My tasks separates Assigned from Created

One list mixed the two, so a task filed for somebody else, or filed with no
assignee at all, read as work to do. Two tabs now, as in the reference tool:
Assigned keeps the due-date buckets, Created covers everything still open
that you filed, grouped by whether anyone holds it yet. `/me/tasks` returns
`created` in place of `createdUnassigned`, and no longer hides the tasks you
handed to someone else.

## Notifications, photos and timezones

- Clicking a notification marks it read. It followed the link and left the
  row glowing as new, with the badge still counting it.
- The profile takes a photo, through the same downscale-in-the-browser path
  as the workspace logo. The avatar was rendered everywhere and settable
  nowhere, so everyone stayed on their initials.
- The timezone is a list of every zone the runtime knows, each with its
  current offset, instead of a typed string that had to be spelled the way
  the IANA database spells it.

## Every MCP write has a read and a rewrite beside it

The second round of the same complaint, from an agent's next run against a
live workspace. A tool that can only append leaves the workspace drifting:
notes could be created and listed but not corrected, so prospect cards kept
the lines that had since moved into custom fields, and a disqualification
note sat next to the stale card it contradicted with no way to reconcile
them.

- `update_note` rewrites a note.
- `list_kb_spaces`, `list_kb_pages`, `get_kb_page` (body as text) and
  `update_kb_page` make the knowledge base reachable and editable -
  `create_kb_page` wanted a `spaceId` that no tool produced.
- `list_users` resolves user ids, and `create_company` / `create_deal` take
  an `ownerId`. Both endpoints always accepted one; nothing could fill it.

Deletion stays out of the catalog, as its rule says: an obsolete note is
rewritten to say what is true now, which keeps the record rather than
dropping it.
