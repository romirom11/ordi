# ordi v1.36.2

An MCP agent can now put images into a task.

## Images in a task from MCP

A task description is rich text, and the app has always let a person paste or
drop an image anywhere inside it. An agent connected over MCP could read that
image (as `![alt](url)` in the text an agent sees), but it had no way to
upload a new one – so a bug report or a how-to with screenshots in the middle
of the steps could not be created from MCP.

There is now a tool for that, `upload_attachment`:

- give it a `filename` and `data` (base64, with or without a `data:` prefix)
  or a `url` to fetch server-side, and it stores the file through the same
  `POST /attachments` path the web app uses (S3, HMAC-signed `src`);
- without an `entityType` the file is an inline image: the tool returns
  `src`/`url` to interleave as `![alt](src)` at whatever positions you want
  inside `text`;
- with `entityType` + `entityId` the file lands in that record's Files
  section instead.

The typical flow for a report with two screenshots at different steps:

```
upload_attachment { filename: "step1.png", data: "<base64>" } → { src }
upload_attachment { filename: "step2.png", data: "<base64>" } → { src }
create_task {
  text: "Step 1: …\n\n![step1](SRC1)\n\nStep 2: …\n\n![step2](SRC2)"
}
```

On an existing task, `get_task` first, keep the `![…](…)` lines you want,
insert the new ones where needed, and write back with `expectedVersion`.
The task tools' `text` docs now describe this interleaving pattern.

## Upgrading

`docker compose pull && up -d` (Dokploy: Redeploy). No migrations.
`POST /attachments` is unchanged – only the MCP catalog gained one tool.
