# ordi v1.3.0

SMTP and the GitHub/Slack OAuth apps are now configured in the app, not in the
server's `.env`.

## Settings → Integrations

**Email** has real fields – host, port, TLS, username, password, from address –
plus two buttons that answer different questions: *Test connection* checks that
the SMTP port answers at all, and *Send test email* proves delivery end to end
by mailing your own account.

**GitHub** and **Slack** show a client ID and secret form until an OAuth app is
configured, with the redirect URL to register on the provider's side displayed
right there. Connecting no longer requires shell access to the server.

Changes apply immediately – no restart.

## How the settings resolve

Anything set in the UI wins. `SMTP_URL`, `SMTP_FROM`, `GITHUB_OAUTH_*` and
`SLACK_CLIENT_*` remain the fallback, so existing deployments keep working
exactly as before, and the settings screen shows when a value is still coming
from the environment.

Secrets are encrypted at rest with `ENCRYPTION_KEY` and never sent back to the
browser – the API returns only whether one is stored. Leaving a password or
secret field blank keeps the stored value.
