The problem

Five subscriptions that never talk to each other

A ten-person agency ends up running on Linear for tasks, a CRM for the pipeline, Notion for documents, a timer app, and something for invoices. The hours logged against a task never reach the invoice. The deal that became a project is retyped by hand. Nobody can answer "did we make money on this client?" without a spreadsheet.

Features

One system, end to end

Everything below runs on the same database, with the same permissions and the same API. Modules you do not need can be switched off – run ordi as just a task tracker, or just a CRM.

Projects and tasks

Deliberately modelled on Linear: keyboard-first, fast, opinionated. The difference is that the work connects to money – a task carries hours, the hours carry rates, and the project tells you its margin.

  • Board, list, calendar, timeline and spreadsheet views
  • Cycles with burn-up, milestones, project updates with health
  • Sub-tasks, dependencies, labels, custom fields
  • Saved views, filters and display options

CRM

Companies, contacts and a drag-and-drop deal pipeline with a weighted forecast. A won deal turns into a project without retyping anything.

  • Leads before qualification, deals after
  • Sales activities, playbooks, sequences and a work queue
  • Client portal links and public intake forms
  • Email intake over IMAP

Finance

Quotes and invoices with tax, discounts, branded localized PDFs and public payment pages. Underneath sits a double-entry ledger – every invoice, payment and expense posts balanced entries, so the books actually balance.

  • Payments, credit notes, recurring invoices, expenses
  • Receivables aging and overdue reminders
  • Invoice straight from unbilled time
  • Project profitability out of the box

Knowledge base

A Notion-style editor with spaces and per-space permissions – the documentation lives next to the work it describes, not in a fifth subscription.

  • Nested pages, versions, backlinks
  • Publishing and Markdown export
  • @ to mention people, # to reference tasks, pages, companies and invoices
And the rest

The parts nobody wants to buy separately

Time

Timers and manual entries against tasks, billable and cost rates, timesheet approval, invoice-from-time.

People

Employee records, org structure, leave with balances, versioned compensation with audited access, recruiting with public careers pages.

Resourcing and dashboards

Capacity planning, team availability and custom dashboard widgets.

Realtime

Assignments and mentions arrive over SSE with a toast and a sound. No refresh, no polling.

Modules you can switch off

Not every team needs HR or a ledger. Turn a module off and it disappears from the navigation, the search and the permissions.

Permissions that hold

Enforced on every request; the UI only hides things. Audit diffs redact sensitive fields, writes use optimistic locking.

Built-in MCP server

Point Claude or Cursor at your workspace

ordi ships an MCP server over its own REST API. Connect an agent and it can plan a cycle, log time, move a deal, chase an overdue invoice or draft a knowledge base page – with exactly the permissions of its API token, and nothing more.

  • OAuth with PKCE, so the client never holds your password
  • Scoped to a token: revoke it and the agent stops
  • Same permission checks as a human on every call

Against Linear and Jira ordi's task experience is deliberately modelled on Linear: keyboard-first, fast, opinionated. The difference is that the work connects to money.
Against Notion and ClickUp Those give you a toolkit and expect you to build the system. ordi ships the system: real invoices, a real pipeline, real leave balances.
Against Odoo Odoo can do all of this and much more, after an implementation project. ordi targets the team that wants to be running today.
Against Twenty Twenty is a beautiful open-source CRM. ordi is a CRM and the delivery and finance system that follows the sale.

Not for you if: you need manufacturing, inventory, payroll runs, or a hundred-seat deployment with SSO and custom workflow engines. ordi is built for teams of roughly 3 to 50 people.

Quick start

Requires Docker. Nothing else.

Terminal 
git clone https://github.com/romirom11/ordi.git
cd ordi
docker compose up --build

# then open http://localhost:8080
  1. 1
    The setup wizard creates your workspace One screen: workspace name, owner account, currency and the modules you want.
  2. 2
    Or start from the demo seed pnpm db:seed builds a full demo agency – clients, a live project with a sprint, invoices with ledger entries, logged time and a knowledge base – so you can judge the product in a minute rather than staring at empty states.
  3. 3
    Deploy it for real docs/deployment.md covers docker-compose or Dokploy with TLS, SMTP, S3-compatible storage, backups and health checks; docs/operations.md covers PITR targets, monitoring and the restore runbook.
  4. 4
    Install the desktop app macOS, Windows and Linux, with native notifications, a global quick-add shortcut and signed auto-updates. It connects to your instance – enter your URL on first launch.
How it is built

Boring where it counts

No Redis, no message broker, no microservices. One Postgres database does the data, the search and the job queue.

Database
PostgreSQL 16 – JSONB, full-text search, triggers
API
Hono on Node 22, TypeScript, Zod-validated, OpenAPI
ORM
Drizzle with SQL migrations
Web
React 19, Vite, TanStack Query, Tailwind
Queue
pg-boss, on the same Postgres
Desktop
Tauri 2
Monorepo
pnpm workspaces + Turborepo
License
AGPL-3.0-only
apps/api         Hono API – domain modules and background workers
apps/web         React SPA (also the desktop UI)
apps/desktop     Tauri shell
packages/db      Drizzle schema, migrations, triggers
packages/shared  Zod schemas, permission catalog, pure calculations
packages/mcp     MCP server over the REST API
